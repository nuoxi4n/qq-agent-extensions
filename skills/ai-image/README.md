# AI生图 · ai-image

面向 [QQ-agent](https://github.com/K0nd1us/QQ-agent) 的图片生成技能，支持文生图和图生图，并将结果直接发送到当前群聊或私聊。

## 安装与配置

将合集中的 `skills/ai-image/` 整个目录复制到 QQ-agent 的 `skills/` 下，或在仓库根目录执行 `npm run pack:extension -- ai-image` 后导入生成的 ZIP。压缩包根目录直接包含 `skill.json`、`index.js` 和 `lib/`，符合市场打包格式。首次安装按宿主的热重载设置加载。

在控制台的「AI生图」设置中填写：

| 配置 | 用途 |
| --- | --- |
| `baseUrl` | 必填，图片 API 前缀，如 `https://example.com/v1` |
| `apiKey` | 必填，密码字段，使用 Bearer 认证 |
| `model` | 默认 `gpt-image-1`，按服务商支持情况修改 |
| `editModel` | 可选，单独指定图生图模型；留空复用 `model` |

支持纯域名、API 前缀以及完整的 `/images/generations`、`/images/edits` 地址。纯域名自动补 `/v1`；其他路径按原样保留为前缀，例如 `https://example.com/proxy/v1`。不要填聊天接口地址。需要 **OpenAI images 兼容接口**：文生图为 JSON POST，图生图为上传单张参考图的 multipart POST；仅支持 chat/completions 的服务不能直接使用。

初次没有配置时，技能同步显示缺少 Base URL/API Key 的原因。修改配置后下一次调用生效，无需重新加载代码。

## 使用

- 文生图：「画一张雨夜城市街景，赛博朋克风格」。
- 图生图：先发参考图，再说「保留这张图的人物姿势，把背景换成雪山」。
- 指定图片：「把消息 #12345 的第 2 张图改成水彩风」。

注册 `gen` 与 `edit` 两个工具（实际名称前缀为 `ai-image__`）。每次生成 1~4 张，同时受管理员配置的单次上限约束，支持可选尺寸。参考图支持 PNG/JPEG/WebP；图片格式、数量、尺寸和参数最终以服务商及模型为准。

确认用户明确要求生图或改图后，主会话模型先通过内置 `send_message` 按当前人设自然告知正在处理，发送成功后调用 `ai-image__gen` / `ai-image__edit`。技能等待生图/改图并发送图片，然后返回结果，要求主会话模型再通过 `send_message` 自然回复完成情况或失败原因。两次文字均由正常主会话产生，技能不生成或发送固定文字，也不另起聊天模型调用。当前对话轮次会等待生图完成。

技能只观察公开的 `ctx.session.sent`：本轮没有非空文字发送记录时，返回“先调用 send_message”的指引，不提交生成请求。记录只能证明本轮有文字发送，不能判断其语义是否确实为开始提醒；具体话术和顺序由提示词引导。图片发出后，工具明确区分“不要重复发图片”和“仍需发送完成文字”，不再把全部回复笼统标为无需发送。生成或发图失败也只返回事实和处理建议，由主会话模型说明。

技能只通过公开的 `api.config()` 读取自己的图片配置，通过 `api.fetch` 访问图片接口，通过 `ctx` 读取当前会话参考图并发送图片。不导入宿主 `src/`、不读取全局聊天配置、不自行组装系统人设或调用主聊天 API。文字回复的人设、权限检查、用量统计和发送均走宿主原有主会话流程；图片接口另有下述独立配额记录。

提示词和工具结果不能强制宿主一定再执行一次 `send_message`。模型选择结束、轮次耗尽或宿主提前收尾时，完成文字仍可能缺失；本技能不声称能硬性保证回复，也不通过内部模块访问来绕过这一限制。要提供强保证，需要宿主公开相应的流程接口。

图生图用 `messageId` 明确选择参考图片；省略时优先使用请求消息自身的附图，否则选择本轮请求边界内唯一的带图消息。本轮没有候选时才读取最近 30 条历史记录，并按请求消息的本地序号排除后来发出的图片。同一范围有多个候选时要求填写 `messageId`，不会猜最新的一张。QQ 图片链接过期时，会尝试协议端提供的其他地址或本地文件。

图片先下载或解码、检查体积与格式，再保存到系统临时目录 `qq-agent-ai-image`，经 `ctx.sender` 发到当前会话。本地路径发送有 `dataUrl` 回退；缓存失败时仍可发送。缓存保留最新 20 张，一小时内文件暂不清理以保护并发发送。会话历史与限频、去重由 QQ-agent 的发送器负责。

API Key 不写入源码，不发送给参考图或结果图的下载地址。默认关闭生成重试；可选重试仅针对 HTTP 429，不能据此保证服务商不计费。图片下载遇到网络故障可以重试一次，生成超时、5xx、断连和发送失败都不会再次调用生成接口。

## 防滥用与用量记录

默认启用次数限制，单次默认上限为 2 张。文生图、图生图和扩展能力统一执行限制，修改设置后下一次调用生效。

| 配置 | 默认值 | 含义 |
| --- | --- | --- |
| `maxImagesPerRequest` | `2` | 单次最多生成张数，可设 1~4；超出直接拒绝，不自动拆单 |
| `dailyUserLimit` | `10` | 同一 QQ 号每天最多提交次数，跨群和私聊合并 |
| `dailyTotalLimit` | `100` | 所有用户与扩展能力每天合计最多提交次数 |
| `totalLimit` | `1000` | 本实例累计最多提交次数，跨日、重载和重启保留 |
| `blacklistEnabled` | `true` | 是否检查黑名单；关闭保留词表，重新开启恢复检查 |
| `blockedTerms` | 空 | 使用中英文逗号、分号分隔；留空表示没有禁词 |

三个次数限制均允许 `0` 表示不限。日额度按 **北京时间（UTC+8）零点**重置，累计次数不自动重置。每日限制范围为 0~1000000，累计限制最大为 JavaScript 安全整数；非法配置会报错，不会静默取消保护。

一次图片接口 POST 计一次，与请求的图片张数无关，同时记录累计请求张数。提交前先保存计数，保存成功才请求接口；HTTP 错误、超时、下载失败、发送失败均不返还，HTTP 429 的每次重试也各计一次。这样可避免不确定计费状态下重复消耗额度；进程恰好在保存后、提交前中断时也会保留该次计数。因此记录表示预扣的接口尝试次数和请求张数，不代表实际成功出图或服务商账单。参数不合法、命中黑名单、参考图无效、缺少开始文字或身份不明等提交前错误不扣次数。

个人身份与选图边界统一从当前宿主的 `ctx.session.trigger` 消息数组解析一次，不接受工具参数指定 QQ 号。多人发言时必须用 `requestMessageId` 指定本轮实际提出生图或改图要求的消息；单人发言时可省略，以该用户最后一条有效消息为边界。编号必须唯一对应本轮消息，不能引用历史、撤回、机器人或拍一拍消息。缺少明确请求时在下载参考图、扣额和生成前拒绝，即使关闭个人日限额也不猜测身份。模型负责按实际请求选择编号，不得选择旁人的消息转移额度。改图的 `messageId` 只选择参考图片，图片作者不决定额度归属。

宿主基线为官方提交 `11577ba`：`session.trigger` 是消息数组，消息 `id` 是本地递增整数。代码只使用这一结构，不读取旧 `triggerEntries`、字符串触发类型，也不以时间戳或 @ 标记兜底。

扩展能力没有可信聊天身份，因此所有 `image.generate` / `image.edit` 调用共用独立的 `provider` 日额度，额度数值同 `dailyUserLimit`，并计入全局每日和累计上限；传入 `userId` 或 `requestMessageId` 不会更换计数身份。

黑名单匹配最终传入的 `prompt` 子串，忽略大小写、Unicode 全半角兼容形式、空白和零宽格式字符。例如配置 `禁词` 后，`禁 词` 也会被拒绝。它不检查参考图内容，不是语义审核，谐音或同义改写也不保证识别。命中后不会下载参考图或请求生图接口；工具会说明被拦截，模型不应改写或拆分请求绕过限制。

黑名单只使用 `blockedTerms`，不读取或迁移旧词表，请在设置中填写当前词表。该字段不会被宿主误判为密钥，保存后可正常回显。清空后表示没有禁词；关闭「启用生图黑名单」可暂停检查并保留词表，重新开启恢复检查。配置解析也支持换行分隔；部分宿主界面只提供单行输入，建议使用逗号或分号。

计数文件为宿主数据目录中的 `ai-image-usage.json`。优先使用 `QQ_AGENT_DATA_DIR`，否则按安装位置使用宿主 `data/`，纯数字 `QQ_AGENT_PROFILE` 对应 `data-<profile>/`。文件保存 `total`（累计次数）、`totalImages`（累计请求张数）、`day`（北京时间日期）、`dailyTotal` 和 `users`（当日各用户次数）。不保存密钥或提示词。额度按共享此文件的实例范围统计；不同数据目录不会合并。即使把次数限制设为 0，仍然记录用量，重新开启后继续按已有记录判断。

每次扣额用文件锁保护，重新读取记录并原子替换保存，防止并发超额。文件损坏、无法读写、日期回拨或锁冲突时停止提交，不清空记录。异常退出可能留下 `ai-image-usage.json.lock` 目录：管理员应先停止所有共用数据目录的实例、备份记录并确认没有请求运行，再移除遗留锁。更新或重装时保留数据文件；累计用量耗尽可调高 `totalLimit`，无需删除历史计数。

## 停用、中止与更新

停用、卸载或重载技能会中断在途 HTTP 请求和重试等待，并阻止旧操作继续提交生成或发送图片。再次启用不会恢复旧操作。已经被服务商受理的请求仍可能计费。

工具在回复、生成、下载和发送边界检查可见的会话状态；观察到 `done`、`noreply`、`aborted` 或 `error` 时停止后续处理。已核对的 QQ Agent API v1 没有向技能传递会话取消信号，因此不能保证“中止”按钮立即打断在途处理。需要停止所有在途生图时可停用技能。已经交给宿主发送队列的消息无法由技能撤回。

重启不会恢复或自动重新提交未完成请求。其他扩展调用 `image.generate` / `image.edit` 能力时只返回图片数据，由调用方负责发送，不触发开始或结果聊天回复。

配置修改下一次调用生效。入口及全部本地模块导入均携带发布版本，版本变更时会一起刷新，避免沿用不执行扣额的缓存模块。不会补记此前未记录的请求，已有用量文件继续保留。覆盖安装同版本的包，或不变更版本而直接修改 `lib/` 时，应重启 QQ Agent。

额外请求字段 `extraBody` 必须是合法 JSON 对象，不能覆盖模型、提示词、图片和数量等核心字段。

## 开发与验证

Node.js 20 或以上，无第三方运行时依赖。以下命令在合集仓库根目录执行。

```text
npm test -- ai-image
npm run test:audit
npm run pack:extension -- ai-image
```

测试使用本地模拟 HTTP 服务和 QQ-agent 上下文，覆盖 JSON/multipart、参考图定位、热更新、图片下载与解码、超时、体积限制、部分失败、密钥脱敏、开始文字记录检查、慢请求等待和返回主模型的回复指引。配额测试覆盖所有调用入口、黑名单、北京时间跨日、重载保留、独立进程并发抢额、失败和重试扣额、损坏数据及身份歧义。边界测试检查模块依赖不越出技能目录，并在没有宿主源码或配置的独立目录执行生图/改图；不需要真实 API Key，也不调用付费接口。测试不代表模型一定遵循回复指引，真实服务商、模型和 QQ 发送需配置后验证。

升级回归测试先缓存不执行扣额的旧模块，再覆盖安装、仅重载入口，验证三个次数限制生效。设置 `QQ_AI_IMAGE_HOST_DIR` 指向已安装依赖、含 `src/` 和 `ui/` 的 QQ-agent 源码目录，可额外运行真实宿主加载器、表单渲染和设置路由测试，检查黑名单回显、保存其他配置、词表替换、关闭、重新开启、清空、额度热更新和重载。发布版本时须同步所有本地模块导入的 `?v=`，边界测试会检查它们与清单版本一致。

`test:audit` 是本项目的清单与工具契约检查，不等于 QQ-agent 全仓审计。安装进 QQ-agent 源码仓库后可再运行其官方 `npm run test:audit`。

本技能在 `qq-agent-extensions` 合集中维护，使用仓库根目录的 Git。
