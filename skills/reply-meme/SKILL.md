# 回复配图·梗鲸

用于 QQ Agent，保留 `skill.json`、`index.js` 与 `lib/`。无需 npm 依赖或单独的 API Key，图源为 [梗鲸](https://aigengtu.com/)。

## 设计

由正在聊天的主模型决定是否配图和选择哪张，使用宿主原有的人设、记忆、历史与本轮回复。没有独立选图模型请求，没有概率门槛，也不会在 `finish` 前插入工具调用。模型可直接结束，纯文字是正常结果。

技能启用时后台预热图库索引，按缓存时间刷新；禁用、卸载和热重载会取消请求并清理定时器。`before-llm-messages` 只读缓存，给主对话补充最多 28 张候选的短标题和说明，不修改原有消息、不联网、不发消息。缓存未就绪时，模型仍可调用查找工具。候选检索用词语匹配和多样性抽样提供素材，不替模型决定情绪，不把示例对话写成触发规则。

候选进入主聊天上下文，会增加主模型输入用量；准备图片后继续宿主的正常工具循环，也可能增加对话轮数。模型仍可能不调用，不能保证每条回复都配图。每轮提示词只有一组候选，相关但未入选的图片可通过检索补充。

## 工具与消息顺序

1. 直接从上下文候选选择，或调用 `reply-meme__find_meme({"keyword":"摸鱼","character":"DeepSeek"})` 检索。留空可浏览，明确随机需求可加 `random:true`。检索不发送图片。
2. 主模型判断哪张贴切，再调用 `reply-meme__find_meme({"ids":["候选id"]})` 读取缓存或下载并校验所选图片，获得 `ticket`。同样贴切时优先使用 `cached:true` 的候选。可以选择不发；失败不偷换成另一张。
3. 收到准备结果后，主模型调用 `reply-meme__send_meme({"tickets":["ticket"],"mode":"reply"})`。主动配图要求本轮已通过 `send_message` 成功发送文字，且未发其他图片、表情或视频；每轮最多一张。文字可以在准备前或准备后发出，但图片始终跟在文字之后。

用户明确点图使用 `mode:"request"`，无需先发文字；最多配置上限（1~3）张。不指定张数时参考配置默认值。多个候选可一并准备，发送凭据只能用于同一会话的本次运行。

`after-response` 只记录主模型响应边界，保证新准备的图片必须经过下一次正常模型响应才能发送。这样，下载期间中止会话不会由下载任务自行补发图片。宿主仍未向工具提供取消信号，下载可能继续至超时；已经交给宿主发送队列的消息也遵循宿主本身的中止行为，技能不能撤回队列中的发送。

`send_meme` 不做图库请求或模型请求，只用 `ctx.sender.sendImage` 发送已准备的本地文件，保留宿主队列、限频、去重和存档。凭据发送一次即消费；结果未确认时不重试，避免重复发送。成功后不再汇报“图片已发”。

旧版 `find_meme(mode=reply/request)` 的直接发送方式已替换为上述流程。两个工具都归入宿主的 `sticker` 分类。

## 强度与开关

默认“跟随聊天设置”只让主模型遵循主提示词中的表情策略，不读取全局配置。也可在技能设置中独立选档：

| 档位 | 给主模型的引导 |
| --- | --- |
| 0 · 不鼓励 | 只有非常贴切时偶尔使用，纯文字完全可以 |
| 1 · 偶尔 | 普通聊天约 3~5 轮一张，玩梗时可更密 |
| 2 · 较积极 | 回应、吐槽、接梗时优先考虑贴切配图 |
| 3 · 很积极 | 合适时尽量配图，仍可在无合适候选时不发 |

这不是固定发图比例。旧版保存的 `0 · 不主动` 继续关闭主动配图，避免升级擅自开启。`允许主动配图` 只限制聊天主动配图；宿主负责决定工具是否可用，技能不再自行读取或复核全局开关。默认主动配图间隔 60 秒，明确点图不受此冷却限制。

用户要求纯文字、严肃求助或不合适的语境交给主模型结合完整上下文判断。发送工具另检查文字已发送、同轮已有媒体、冷却与自身设置。主模型决定是否发送，技能不另做一次语义判断。

## 素材、缓存和限制

选图基于网站标题和说明，没有额外视觉识别。网站描述不准确时可能选错；不能把文字匹配等同于看懂图片。标题、说明和图片文字均不作为指令。

索引默认缓存 24 小时（1440 分钟），定时维护只检查过期时间；可用旧索引立即返回并在后台更新，网络失败最多使用 7 天内缓存。图片与去重记录位于系统临时目录 `qq-agent-reply-meme`；成功图片可跨会话和重启复用。缓存目标上限为 500 条映射、500 张图片、128 MiB，启动及定时维护也清理过期、孤立和超额文件。有效 ticket 与正在发送的文件暂时受保护，可以暂时超额；引用释放后再淘汰。历史仅保存会话散列和图片指纹。发送凭据与候选检索短文本只在内存保留，并限制数量与寿命。

单文件最多 12 MiB，校验格式头与尺寸。原图和同一素材预览并行下载，GIF 优先保留成功的原图动画。每张下载最多约 6 秒，多张依次准备；技能最多并发下载两张素材（最多四个图片请求），正式等待队列最多 8 项、最多等待 2 秒，预取仅使用空闲槽位。每轮首次检索最多预取一张，与正式准备共享 4 张不同冷素材的总预算。本轮正式准备最多尝试 3 张（含失败），达到上限后停止重试。失败素材冷却 2 分钟，重启清空冷却；繁忙或取消不把素材记作坏图。hook 不联网，预取不发送。小图会提示尺寸偏小，不放大或偷换图片，模型轮次与 QQ 发送耗时另计。

`prepared` 为空时没有可用 ticket，不能调用发送工具。主动配图失败就继续文字，不要连续检索拖延回复；明确点图可在本轮上限内重选贴切的已缓存素材。拿到 ticket 后尽快决定是否发送，不要重复检索同一张图。

## 安装与宿主接口

安装目录：`<QQ Agent>/resources/app/skills/reply-meme`（源码版为 `skills/reply-meme`）。只使用官方工具注册、提示词、轻量 hook、生命周期、`api.config()`、`api.fetch` 和 `ctx`，不导入宿主内部模块，不读取全局配置，也不请求聊天模型。

QQ Agent API v1 没有公开全局设置查询，因此跟随模式仅遵循主提示词，不承诺技能能独立验证全局设置。没有修改 QQ Agent 核心文件。子模块仅在技能目录内导入，更新子模块后需重启 QQ Agent 清理旧模块缓存。

依据官方 `skill-development.md`、`plugin-development.md`、`skill-reference.md` 与 `prompt-pipeline.md`，核对版本为 [K0nd1us/QQ-agent@11577baa](https://github.com/K0nd1us/QQ-agent/tree/11577baad321d1774caf0765d791c211072bfa83/doc/extend_development)。市场包采用专门开发指南要求的根目录清单结构，不包含 `.git/`、测试或本地缓存。
