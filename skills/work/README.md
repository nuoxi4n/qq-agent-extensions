# 趣味打工 · work

当前版本 **1.0.1**，修复进程退出遗留锁，以及删锁暂时失败后的重新启用和热重载恢复。

选择职业，赚取当前群配置的货币。程序抽取事件和工资并入账，主会话 AI 把结果写成符合角色人设的短篇打工经历，无需额外模型接口或 API Key。

预置 **奶茶店员、外卖骑手、程序员、星际清洁工**。默认每人每群每天 3 次、间隔 2 小时，每次收入 10～80，故事目标约 120 字。职业和事件都可以修改。

## 安装

1. 安装并启用货币系统 `currency`。
2. 导入 `work-1.0.1.zip`，或把本目录复制到宿主 `skills/work/`，清单为 `skill.json`。
3. 在货币系统的「扩展接入权限」JSON 对象中增加 `"work": ["credit"]`，保留其他扩展原有权限。例如原来为空时填写：

```json
{"work": ["credit"]}
```

4. 在「技能」页启用趣味打工，调整职业、收入和事件。

不需要配置主人 QQ；本版通过宿主设置页管理配置，不提供聊天修改配置的工具。货币名从 `currency.v1` 实时读取，不维护第二套钱包。各群和私聊的账户、次数、冷却分别独立。

### 从早期插件目录迁移

1. 停止宿主，备份数据目录中的 `config.json`、`work.json` 和 `currency.json`（存在时）。
2. 将旧的 `plugins/work/` 整个移到宿主 `plugins/`、`skills/` 以外的位置留作备份，再安装新版到 `skills/work/`。不要同时保留两个同 ID 的扩展，也不要只在 `plugins/` 内改目录名。
3. 启动宿主，在「技能」页确认趣味打工生效。现有 `work` 配置、货币接入权限、余额、每日次数、冷却、待结算记录和去重编号继续沿用。

技能版 1.0.0 按官方的 LLM 型扩展分类使用技能目录和清单。扩展 ID、工具前缀 `work__`、货币消费方 `work`、数据位置与格式均保持不变，不需要清空或转换存档。导入 ZIP 前也应先移走旧目录，避免同 ID 冲突。

## 怎么玩

- “有什么职业可以打工？”
- “去奶茶店打工。”“我要当程序员打工。”
- “随机打个工。”（未指定职业时，从开放职业中等概率选择）
- “今天还能打几次？”“看看我最近的打工记录。”
- 有待结算记录时再次说“打工”，只恢复原单；恢复成功后，下一条新的打工请求才会开始新单。

工具为 `work__jobs`、`work__play`、`work__status`。工具只返回数据；主模型通过 `send_message` 发送故事和结果。普通聊天不会自动触发打工。模型轮数耗尽或未执行发送时可能没有故事，但已确认入账的工资不会因此撤销，可查询原记录。

## 配置

| 设置 | 默认 | 说明 |
| --- | --- | --- |
| 默认最低／最高收入 | 10／80 | 正整数；职业可分别覆盖；含特殊事件的最终边界 |
| 每人每天打工次数 | 3 | 同一会话所有职业共用；0 暂停新打工 |
| 打工间隔 | 7200 秒 | 所有职业共用，跨日保留；0 关闭 |
| 每日额度时区 | Asia/Shanghai | 自然日；修改后按记录时间重新计算当天次数 |
| 故事目标字数 | 120 | 40～300，模型软约束，不是硬 token 上限 |
| 故事风格补充 | 轻松幽默 | 最多 400 字，可留空 |
| 职业和事件（JSON） | 四个预置职业 | 最多 30 个；数组 `[]` 暂停新打工 |

修改下一次调用生效；不改变已经保存的事件和工资。初始配置错误也会初始化存储，修正配置后即可使用；修改运行模块后需重启宿主。各群共用这一实例的职业配置，但次数和账目不互通。

### 职业字段

必填 `id`（稳定英文编号）、`name`（名称）、`description`（AI 创作背景）。选填 `aliases`（别名数组，最多 8 项）、`enabled`（默认 true）、`minReward`、`maxReward`、`events`。

名称、别名和 ID 不得与其他职业冲突，匹配忽略大小写。输入未知职业时提示可选项，不擅自改为随机职业。关闭职业不影响旧单恢复。默认收入上下限最大支持 1000000000000，与货币接口一致。

没有 `events` 时自动使用下列事件。示例收入是默认 10～80 下的结果；调整职业范围会同步重算各段。

| 类型 | 概率 | 默认收入 | 事件方向 |
| --- | --- | --- | --- |
| 不顺 | 15% | 10～19 | 小岔子，工资较少，仍保留收入 |
| 普通 | 75% | 20～40 | 工作中的有趣插曲 |
| 好运 | 8% | 41～65 | 小费、表扬、表现出色 |
| 稀有 | 2% | 66～80 | 神秘客户、意外救场 |

收入整数区间按 15%、45%、80% 的分界分段，金额在选中段内均匀抽取；极窄范围可能让不同事件有相同工资。这些事件不扣已有余额，不另发故事中编造的小费。

### 自定义事件示例

以下是一个完整可复制的职业数组，会替换设置中的整份职业列表。想保留预置职业，可把新职业对象追加进原数组。

```json
[
  {
    "id": "tea",
    "name": "奶茶店员",
    "aliases": ["奶茶工", "调饮师"],
    "description": "一家经常收到奇怪订单的奶茶店，围绕顾客、调饮和店长创作。",
    "enabled": true,
    "minReward": 10,
    "maxReward": 80,
    "events": [
      {"id": "spill", "name": "手忙脚乱", "weight": 15, "minReward": 10, "maxReward": 19, "prompt": "制作过程出了小岔子，但仍完成工作。轻松吐槽，不扣已有余额。"},
      {"id": "normal", "name": "平常的一天", "weight": 75, "minReward": 20, "maxReward": 40, "prompt": "围绕一份奇怪订单自由编写一个小插曲。"},
      {"id": "tip", "name": "意外小费", "weight": 8, "minReward": 41, "maxReward": 65, "prompt": "顾客很满意，工资已包含小费，不要另加金额。"},
      {"id": "boss", "name": "神秘顾客", "weight": 2, "minReward": 66, "maxReward": 80, "prompt": "顾客竟然是来暗访的老板，因为你处理了一件离谱小事而特别表扬。"}
    ]
  }
]
```

每个事件必填 `id`、`name`、`weight`、`prompt`，收入范围可省略（继承职业范围）。事件概率是自身权重除以该职业权重总和，不需要权重总和恰好为 100。权重为 0 会停用该事件；至少一个事件必须大于 0。最多 30 个事件，单个权重为 0～1000000 的整数。

事件收入必须完全落在职业范围内，特殊事件也一样；超出时报告具体字段位置，不静默截断。事件提示最多 500 字，职业背景最多 400 字。剧情提示只提供创作素材，不能改变领取资格、金额或交易参数。模型不会收到未抽中的事件库。

## 结算、恢复与数据

数据保存在宿主数据目录 `work.json`，优先遵循 `QQ_AGENT_DATA_DIR`，其次遵循数字 `QQ_AGENT_PROFILE` 的 `data-N`，默认 `data`。不读取宿主内部源码、全局聊天配置或其他插件数据文件。

每次打工绑定当前会话、真实操作人和消息编号，先保存职业、事件、金额与风格快照，再通过 `currency.v1.credit` 发奖，最后保存完成标记。只有来自本人本轮的请求可领取，工具不接受金额、概率或目标 QQ 参数。混有不同发言者的触发批拒绝操作；复杂自然语言是否明确要求打工仍依赖主模型判断。

- 同条消息重试返回原结果，不再次抽取或占用次数；修改原职业参数会报冲突。
- 使用新消息恢复旧单时，这条恢复消息也永久关联到原单；完成后重试该消息仍不会开始新单。
- 待结算记录已占用次数和冷却，阻止本人再创建新单。即使跨日或修改职业也先恢复旧单。
- 发奖结果丢失时先查询原交易回执；需要重试时复用同一业务编号、金额与原因。不会用新编号绕过冲突。
- 钱已到账但本地完成标记保存失败时，明确返回已到账和待恢复状态，下一次仅核对并补记；不重复入账。
- 状态查询不发奖。对待结算记录只读核对回执，展示已到账、待发放或未能确认。
- 同步保存与货币同步 API 保证本宿主中的同一轮操作不中途交错。独占 `work.json.lock` 与配套 `.lock.owner-<PID>-<UUID>` 归属文件阻止两个实例同时使用同一数据文件，正常停用或进程退出时清理。
- 强制结束后的遗留锁在下次启用时确认原 PID 已退出后自动回收，兼容旧版 PID 锁；活进程或归属无法确认的锁仍会阻止启动，同时启动可能相互退让，可稍后重试。数据目录需支持同目录硬链接（如本机 NTFS）。仍冲突时，确认所有实例已退出再排查锁与归属文件，不要删除 `work.json` 或货币流水。
- 存储损坏时保留文件并停止操作，不静默清零。
- 停用时删锁暂时失败，会保留原归属记录，在重新启用（含热重载）、再次释放或进程退出时安全重试；清理完成前不恢复写入，不删除其他实例的锁。
- 不设置后台恢复定时器；用户下一次打工触发原单恢复。无权发奖时新单不占次数，已有待结算记录保留。

正常停用后应一起备份 `work.json` 与 `currency.json`。不要只删除其中一份或删除旧记录：两者保存事件和交易的永久去重依据。更改宿主时间倒退时暂停新打工，校准时间后恢复。

适用于单宿主、中小规模群娱乐。本版每次保存完整打工记录、扫描本人次数，数据量随使用增长。故事正文由主会话生成，本技能只保存确定的事件素材和结算结果；重述时措辞可能不同，不承诺保存原文或永不重复剧情。

## Token 用量

不额外请求生成模型，复用主会话；工具本身无网络请求或 AI 调用。职业列表只返回名称和收入范围，打工结果只返回选中职业、事件提示、金额和配额，一次调用即可完成查询和结算，避免再查余额。默认故事目标约 120 字。

常驻工具定义及短提示仍可能增加普通聊天输入，完整职业配置和事件库不会注入所有聊天。长职业背景或事件提示会增加本次输入；故事字数是软约束。输入还包括工具循环重复携带的聊天历史，缓存及推理输出计费由宿主和模型决定，不能把“没有独立模型调用”理解成零额外 token。

目前未实测 QQ 群聊 usage，不能承诺固定请求次数、token 数或费用。联调时应从宿主统计中对比普通短回复与一次打工的请求次数、输入、缓存输入、输出以及模型报告的推理用量；本技能不伪造计费统计。
