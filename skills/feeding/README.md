# 趣味投喂 1.0.1

1.0.1 修复进程退出遗留锁，以及删锁暂时失败后的重新启用和热重载恢复。建议同时更新货币系统至 1.0.1、好感度养成至 1.2.1，以完整应用锁修复。

购买食物后立即投喂机器人，由当前主会话模型按人设回应。普通模式按食物固定加好感度；AI 模式由模型结合实际互动判断，允许 0 分，默认不扣分、不播报评分。技能没有单独的模型接口，也没有背包。

## 必装前置

- **货币系统 currency 1.0.0 或兼容更新版**，提供 `currency.v1`。
- **好感度养成 rapport 1.2.0 或兼容更新版**，提供通用事件接口 `rapport.v1`。旧版 1.1.0 不提供此能力，需升级。
- 两者都须安装、启用；技能清单通过 `requires` 检查能力。趣味打工只是可选收入来源，不是前置。

将两个插件装入宿主 `plugins/`，投喂装入 `skills/feeding/`，或导入对应 ZIP。升级好感度前先停用并备份宿主数据目录中的 `rapport.json`，升级后重启宿主，保留已有好感度记录。

在货币系统的「扩展接入权限」中**合并**以下条目，保留已有 work 等配置：

```json
{"feeding":["reserve","capture","release"]}
```

在好感度养成的「扩展接入权限」中也合并：

```json
{"feeding":["recordEvent","rateEvent","bindMessage"]}
```

两处权限分别配置，默认不会自动授权。投喂不需要货币的 credit、debit、refund 或好感度的 decrease 权限。缺前置或权限时会明确报错，新订单在预扣前检查。实际货币名称沿用货币系统设置。通用 API 允许其他扩展申请扣分，但投喂始终只接受非负评分。

## 使用

- 「看看投喂菜单」：列出名称、价格和普通模式奖励。
- 「花 35 金币买杯奶茶投喂你」或「买个小蛋糕喂你」：按配置价格购买并投喂一次。报价改变时应重新查看菜单；模型不能传入自定价格。
- 「我的投喂记录」：查看最近三单、次数和冷却。
- 「恢复投喂」：恢复本人未结算或未评分的原单，不再购买。恢复后再发新消息才会开启新订单。

真实发言者必须唯一；多人合并触发、引用或转述不能代替别人购买。普通聊天不消费，免费赠送的角色扮演不购买。自然语言意图由主模型理解，程序核验消息作者、编号、有效时间和配置价格。

## 配置

默认每天 3 次、间隔 30 分钟，普通模式默认奖励如下：

| 食物 | 价格 | 固定好感度 |
| --- | ---: | ---: |
| 小饼干 | 20 | +0.10 |
| 奶茶 | 35 | +0.15 |
| 小蛋糕 | 60 | +0.20 |
| 爱心便当 | 100 | +0.30 |

每种食物支持 `id`、`name`、`aliases`、`price`、`fixedGain`、`description`、可选 `reactionHint` 和 `enabled`。最多 50 种，名称和别名不能跨食物重复；价格为 1～1000000000000 的整数；固定加分为 0.01～10，精度 0.01。`foodsJson=[]` 或 `dailyLimit=0` 暂停新购买，已有订单仍可恢复。

```json
[
  {
    "id": "pudding",
    "name": "焦糖布丁",
    "aliases": ["布丁"],
    "price": 30,
    "fixedGain": 0.15,
    "description": "口感细腻，表面有一层微苦焦糖。",
    "reactionHint": "可以围绕焦糖的香味展开自然反应，不强制喜欢。",
    "enabled": true
  }
]
```

菜单与订单、恢复记录均不常驻注入提示词。购买后只返回当次食物的短资料，`reactionLength` 默认约 60 字，仅为表达建议，不是 token 硬上限。

## 评分与人设

每次创建订单读取好感度插件当前有效模式，包括聊天配置覆盖。订单保存模式和单次 AI 上限；已交付订单恢复时不切换奖励方式。若尚未交付就遇到模式改变，会取消原预扣。

普通奖励是额外的固定食物奖励，与聊天累计共享每日正向上限，使用独立投喂冷却。当天已知额度不足以完整发放、好感度满分或主人固定满分保护时，购买前拒绝，不扣钱。普通聊天原本产生的加分仍按现有规则执行。

AI 模式不保证购买会加分，也不保证贵的食物加分更多。模型须对成功事件提交评分，允许明确评 0；程序限制在订单保存的 AI 单次上限、当前上限、当日剩余额度和 100 分边界内。日常 `rapport__adjust` 不得再对同次投喂加减；若它先评了分，投喂会拒绝交付并取消预扣。AI 待评记录可恢复，恢复时按评分发生当天额度结算，不回写历史日；模式切换不把原 AI 订单变成固定奖励。重置好感度后，旧待评事件关闭为 0，不恢复旧分。

工具 `feeding__menu`、`feed`、`rate`、`status` 只返回数据；反应一直由主模型使用原人设、上下文和 `send_message` 生成发送，不接管发送、不强制结束会话。评分与不涉及实际分值的回复可以同轮生成，但模型不保证总是合并调用。

## 持久化与失败恢复

先保存固定价格订单，再预扣，登记好感度事件，最后结算。**跨插件不是原子事务**：评分交付后结算遇到故障时保留预扣和原事件，只恢复同一单；未知结果绝不自动退款。确认未交付才释放预扣。已完成投喂但回复没发送，费用和奖励不会撤销。

已核实并保存购买成功后，附加的当前关系查询失败不会改变支付结果：工具仍返回 `paid=true`，关系信息暂缺，并明确提示不要重新购买。固定或已完成评分沿用本次事件回执；AI 待评事件仍需评分，暂缺当前额度时返回订单保存的上限，实际评分继续受当前好感度额度限制。购买前的关系查询失败仍阻止新订单和扣款。

每条真实请求只对应一个订单；新消息恢复也绑定旧单。永久事件回执保证重试、重启和跨日不会重复加分，0 分也不可重评。尚未完成的订单阻止本人继续新购买。currency.json、rapport.json、feeding.json 应停用后共同备份和恢复，不要只回滚其中一个文件，也不要删除历史回执。人工释放预扣前须停用投喂，确认无已交付事件。

数据为宿主数据目录的 `feeding.json`，好感度事件在 `rapport.json` 内；遵循 `QQ_AGENT_DATA_DIR` 和数字 `QQ_AGENT_PROFILE`。投喂、好感度和货币各有独占 `.lock` 与配套 `.lock.owner-<PID>-<UUID>` 归属文件。正常停用或进程退出会清理自己的锁；强制结束后，下次启用确认原 PID 已退出便自动回收，兼容旧版 PID 锁。活进程或归属无法确认的锁仍会阻止启动，同时启动可能相互退让，可稍后重试。数据目录需支持同目录硬链接（如本机 NTFS）。仍冲突时，确认所有实例已退出再排查锁与归属文件，不要删除业务存档。

损坏数据停止写入，不自动清空。适用于单机中小规模玩法，数据随使用累积，每次完整写盘。修复锁问题时应一并更新货币、好感度与投喂，再重启宿主使子模块生效。

停用时删锁暂时失败，会保留原归属记录，在重新启用（含热重载）、再次释放或进程退出时安全重试；只重试清理，不补交业务操作，也不会删除其他实例的锁。

## Token 与验证

购买、余额检查、预扣、结算和固定加分只执行本地代码。自然语言入口和反应使用宿主主模型；AI 评分可能增加一轮请求。每轮包含宿主上下文和工具定义，所以不能保证只消耗几十字，也不能保证固定省一轮。未配置独立模型，不后台重试模型，不发送网络请求。实际消耗须在自己的模型与群聊上下文中查看宿主用量记录；本地测试不能替代真实 token 测量。

开发验证：`npm test -- feeding rapport currency`；打包：`npm run pack -- feeding rapport`。真实宿主加载测试可配置 `QQ_CURRENCY_HOST_DIR` 指向 QQ Agent 源码快照，测试不连接 QQ、不调用模型。

1.0.0 在 QQ Agent 0.4.0 源码快照（`11577baad321d1774caf0765d791c211072bfa83`）中验证：三个相关扩展共 130 项本地与宿主集成检查通过，覆盖通用 v1 权限、事件隔离、本地试用数据迁移和付款后附加查询失败；安装 currency、rapport、work、feeding 的隔离副本通过官方审计 34 项。尚未进行真实 QQ 群聊与模型用量实测。
