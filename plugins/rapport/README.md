# 好感度养成

**rapport 1.0.0 · 作者 nuoxi4n**

为 QQ Agent 提供独立的好感度和关系表达系统。高好感会改变机器人对具体群友的语气、称呼、关心和接话方式，每轮回复自动生效，不需要先问“我的好感度是多少”。

## 关系如何影响回复

| 关系 | 表达特点 |
| --- | --- |
| 陌生 | 礼貌、直接，保持适当距离，不假装熟悉 |
| 眼熟 | 更随意，可以接梗，减少客套 |
| 熟人 | 自然使用认可的昵称，适度调侃和接话 |
| 老友 | 明显熟稔，情绪回应更具体，减少客服套话 |
| 挚友 | 开场体现在意，愿意认真听、自然关心，嘴硬角色也能露出心软 |

默认强度为 **3（明显）**。机器人保留现有人设，用关系程度调整社交距离；高好感不只体现为更换称号或增加语气词。实际措辞由使用的模型、角色和上下文决定。

共同经历和习惯只取已有聊天上下文及记忆，不凭积分编故事。同一群的不同成员分别处理；不同群和私聊各自记录关系。没有明确对话对象的主动轮次不套用某位高分成员的关系。

## 安装

在 QQ Agent 插件市场安装，或将发布包完整解压到 QQ Agent 的 `plugins/rapport/` 目录。请一并保留包内的 `lib/` 子目录。支持热重载的版本会自动加载。

在「插件」页找到 **好感度养成**。启用插件后，关系就会自动影响回复，高好感风格默认为“自然亲近”。无需填写机器人 QQ 号，也无需额外 API Key、模型接口或 npm 依赖。

## 可调整的设置

- **回复变化强度**：1 含蓄 / 2 自然 / 3 明显。
- **高好感表达风格**：自然亲近 / 温柔关心 / 熟人拌嘴。
- **高好感表达补充**：为老友和挚友统一补充表达偏好，例如“熟悉时更爱开玩笑”；留空使用默认规则。
- **加分与门槛**：发言加分、@机器人奖励、每日上限、等级门槛。
- **防刷分**：同一人加分间隔默认 30 秒，重复内容去重默认 10 分钟；设为 0 可关闭对应限制。
- **衰减**：默认 7 天未互动后每天扣 1 分，可关闭。
- **主人 QQ 号**：默认留空。选填后，指定账号固定满级，并可在聊天中修改设置、执行重置。固定分数由程序自动保证达到最高等级门槛。

配置页共 12 项。机器人身份直接使用 QQ Agent 的消息标记；补扫窗口由程序管理，排行榜默认 10 人（查询时仍可指定人数）。没有额外的关系功能开关或升级提示开关；关闭整个插件即可停止生效。重置始终只允许主人执行。

查询示例：“我的好感度”“我们现在有多熟”“好感度排行”。配置主人后，主人可说“把回复变化强度改成 3”“把高好感表达风格改成温柔关心”。

聊天修改保存在本插件数据的 `meta.overrides` 中，优先于控制台设置。主人可要求清除某项或全部聊天修改，恢复控制台值。模糊的同名目标需要用 QQ 号明确指定；无法唯一确认发送者的修改请求不会执行。

## 独立数据

- 插件 ID、工具前缀、配置分区均为 `rapport`。
- 数据文件为 QQ Agent 数据目录中的 **`rapport.json`**。
- 数据带有本插件的 `pluginId` 和格式版本标记。
- **不读取、导入或迁移其他好感度插件的分数、主人名单和配置。首次使用从本插件的新记录开始。**

计分在机器人被触发时补扫当前会话最近 200 条消息，范围限于最近 24 小时。新安装时可以统计此范围内的聊天消息，这不是从其他插件导入数据。超出补扫范围且未被处理的消息不会补记。

每日上限、冷却和重复内容去重同时生效。读取 QQ Agent 存档中的 `atMe` 标记；本地序号和 QQ 消息 ID 分开去重，迟到的历史消息不会重置今天的加分额度。

当前 QQ Agent 0.4.0 将引用信息渲染为文字，没有向插件提供可靠的引用消息 ID，因此不设置引用奖励，也不根据昵称或引用文字猜测加分。昵称信息缺失时，只有查询工具会调用 `get_group_member_info` 补全，接口失败仍可用 QQ 号查询。

原子写入保护存档；格式不匹配或嵌套数据损坏时停止写入并报错，不静默清零。停用时同步保存已完成的变更，并取消尚未完成的处理，适应宿主不等待异步清理的加载流程。

插件不主动增加群消息或私聊，不额外发送升级提示。

## 开发

这是确定性插件：`before-context` 每轮计分并识别触发人，`promptSections` 提供动态关系规则，优先级 65。查询和设置通过 `registerTool` 提供给模型。

钩子不联网、不调用额外模型、不发送消息。关系规则遵守 QQ Agent 核心安全与工具协议；高好感不会赋予管理权限。生命周期会清理定时器与运行缓存。

入口只负责加载模块和导出插件接口，业务代码按职责拆分：

```text
plugin.json
index.js
lib/
  plugin.js          实例组装、生命周期和钩子
  config.js          配置、校验和聊天覆盖
  levels.js          等级、衰减和主人规则
  messages.js        消息解析
  scoring.js         去重、防刷和计分
  storage.js         独立存档与原子保存
  relationship.js    关系缓存与回复风格
  utils.js           通用纯函数
  tools/
    index.js         工具注册和参数校验
    context.js       身份校验和查询辅助
    check.js         个人查询
    rank.js          排行榜
    tune.js          设置管理
    reset.js         重置记录
README.md
```

所有业务模块使用普通静态 `import`，插件不为 JS 路径追加版本参数。子模块通过工厂创建独立实例，依赖由 `lib/plugin.js` 显式组装。

当前 QQ Agent 的热重载只重新执行入口，不清除 Node 的 ESM 子模块缓存。因此，修改 `lib/` 中的代码后，需要重启 QQ Agent 才能确保新代码生效；首次安装和配置调整不需要这样处理。这里遵循标准模块加载，不实现额外的文件更新或缓存绕过机制。

运行环境为 Node.js 20 或以上版本。开发命令由合集仓库根目录的 `package.json` 统一维护，插件目录不需要单独的 npm 包配置。在仓库根目录运行 `npm test -- rapport` 可执行通用检查；运行 `npm run pack:extension -- rapport` 可打包本插件。

发布包包含根目录的 `plugin.json`、`index.js`、`README.md` 以及完整 `lib/` 目录，共 17 个文件。不要将 Git 信息、配置或运行数据加入发布包。

开发接口依据：[QQ Agent 官方扩展文档](https://github.com/K0nd1us/QQ-agent/tree/main/doc/extend_development)。
