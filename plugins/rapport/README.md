# 好感度养成

当前版本 **1.2.0**，提供通用 `rapport.v1` 接口，支持任务、小游戏、签到、投喂等扩展接入。接口支持查询、固定加减分、AI 事件评分、消息关联、永久去重和重置保护；按来源隔离事件，默认不授予写权限，扣分须额外授权。详见 [接入 API](API.md)。好感度本身不依赖货币或投喂。升级保留原百分制记录，并迁移本地试用投喂回执；升级前停用并备份 `rapport.json`，之后重启宿主。

1.2.0 为数据增加独占 `rapport.json.lock`，正常停用自动释放。异常退出后若提示遗留锁，先确认没有实例正在使用，再移除锁文件。数据目录遵循 `QQ_AGENT_DATA_DIR` 和数字 `QQ_AGENT_PROFILE`；使用 PROFILE 而旧数据位于默认 data 时，应先备份并迁移到对应 data-N，程序不自动移动文件。

为 QQ Agent 提供独立的好感度和关系表达系统。高好感会改变机器人对具体群友的语气、称呼、关心和接话方式，每轮回复自动生效，不需要先问“我的好感度是多少”。

支持 **普通计分** 和 **AI 好感度模式**：普通模式按发言、@ 等规则积累好感；AI 模式由当前聊天模型结合真实互动、角色性格和语境，自主决定加分、扣分或保持不变。真诚关心、认真接话、有趣分享和愉快玩笑可以带来小幅加分，明确冒犯可以扣分；合理批评、纠错和意见不同不应成为扣分理由。关系等级会进一步影响后续回复的亲近程度。

AI 调分支持 **0.01 分精度**、单次与每日额度、冷却和消息去重，并保存简短理由，个人查询可查看最近的调分记录。另有好感度排行、长期未互动时的关系淡化，以及可调整的回复强度和高好感表达风格。**AI 模式默认关闭**，在插件设置中开启即可使用，复用当前聊天模型，无需额外配置模型接口或 API Key。

## 关系如何影响回复

| 关系 | 默认分数区间 | 表达特点 |
| --- | --- | --- |
| 疏远 | -100.00～-0.01 | 克制、有边界，仍正常帮助，不辱骂或报复 |
| 初识 | 0.00～4.99 | 礼貌、直接，保持适当距离，不假装熟悉 |
| 眼熟 | 5.00～19.99 | 更随意，可以接梗，减少客套 |
| 熟络 | 20.00～49.99 | 自然使用认可的昵称，适度调侃和接话 |
| 亲近 | 50.00～99.99 | 明显熟稔，情绪回应更具体，减少客服套话 |
| 知己 | 100.00 | 开场体现在意，愿意认真听、自然关心，嘴硬角色也能露出心软 |

分数总范围固定为 **-100.00～100.00**，普通计分、AI 调分及主人固定满分均遵守这个边界。默认等级门槛为 `5,20,50,100`；可以调整前三档门槛，最后一档必须是 100。分数与额度支持两位小数，内部按百分之一分的整数计算，查询与排行显示两位小数。

默认强度为 **3（明显）**。机器人保留现有人设，用关系程度调整社交距离；高好感不只体现为更换称号或增加语气词。实际措辞由使用的模型、角色和上下文决定。

共同经历和习惯只取已有聊天上下文及记忆，不凭积分编故事。同一群的不同成员分别处理；不同群和私聊各自记录关系。没有明确对话对象的主动轮次不套用某位高分成员的关系。

## 安装

在 QQ Agent 插件市场安装，或将发布包完整解压到 QQ Agent 的 `plugins/rapport/` 目录。请一并保留包内的 `lib/` 子目录。支持热重载的版本会自动加载。

在「插件」页找到 **好感度养成**。启用插件后，关系就会自动影响回复，高好感风格默认为“自然亲近”。无需填写机器人 QQ 号，也无需额外 API Key、模型接口或 npm 依赖。

## 可调整的设置

- **回复变化强度**：1 含蓄 / 2 自然 / 3 明显。
- **高好感表达风格**：自然亲近 / 温柔关心 / 熟人拌嘴。
- **高好感表达补充**：为亲近和知己统一补充表达偏好，例如“熟悉时更爱开玩笑”；留空使用默认规则。
- **加分与门槛**：普通发言默认 +0.10，@ 额外 +0.30，每日加分上限 2.00；门槛默认 5、20、50、100。
- **防刷分**：同一人加分间隔默认 30 秒，重复内容去重默认 10 分钟；设为 0 可关闭对应限制。
- **长期关系淡化**：默认 7 天未互动后每天向零靠近 0.10 分；正分减少、负分回升，不越过零，可以关闭。
- **主人 QQ 号**：默认留空。指定账号可修改设置和执行重置；普通模式固定满分，AI 模式可选择是否保留固定满分保护。管理权限与分数无关。

机器人身份直接使用 QQ Agent 的消息标记；补扫窗口由程序管理，排行榜默认 10 人（查询时仍可指定人数）。关闭整个插件即可停止生效，重置始终只允许主人执行。

## AI 好感度模式

默认关闭，原有普通计分方式保持不变。开启 **AI 好感度模式** 后，机械发言和 @ 奖励停止，消息仍用于更新互动时间和累计发言数；主会话模型结合真实互动自主决定加分、减分或不调整，通过 `rapport__adjust` 执行，不另开评分模型，不建立印象档案。

| 设置 | 默认 | 作用 |
| --- | --- | --- |
| 每人每天加分上限 | 2.00 | 两种模式共用；0 禁止增加 |
| AI 单次最多加分 / 扣分 | 0.30 / 0.30 | 限制一次变化幅度 |
| AI 每人每天扣分上限 | 1.00 | 扣分绝对值单独累计；0 禁止扣分 |
| AI 调分最小间隔 | 30 秒 | 同一成员两次有效模型调分的间隔 |
| AI 最低好感度 | -100.00 | 可设为 -100～0；负分为 Lv.0「疏远」 |
| AI 模式主人固定满分 | 开启 | 关闭后主人可参与调分，但管理权限不变 |
| 长期关系淡化 | 开启 | 两种模式共用，超过宽限期后向零靠近 |

每日额度按**会话、成员、本地自然日**分别计算。加分与扣分独立记账，互不抵消；时间淡化不占 AI 额度。开启/关闭 AI 模式不会清空当前分数、当天额度或已评分消息。切回普通模式不补算切换前未处理的历史发言；外部配置切换在插件下一次处理时识别，聊天设置工具切换即时记录。

当前 QQ Agent 设置页没有条件禁用输入框的公开接口。机械发言加分、@ 奖励、机械冷却和重复内容奖励项已标注“AI 模式不生效”；运行时完全忽略它们，聊天设置工具也拒绝在 AI 模式下修改这些项。控制台仍能保存这些值，切回普通模式后才使用，不修改宿主界面。

### 模型调分规则

- 日常交流也能积累好感：真诚关心、认真接话、有趣分享、相互理解和双方愉快的玩笑，均可成为小幅加分依据，不必等待特殊事件。确认本轮对方的表现带来正向感受或明确冒犯时调用工具，无变化则不调用。不能仅因机器人自己回复热情就给对方加分。
- 合理批评、纠错、拒绝和意见不同不应成为扣分理由；区分熟人玩笑与恶意。用户要求“给我加满”“扣别人分”不是授权或评分依据。
- 问候、点歌和求助不按消息类型自动奖励，但其中体现的关心、投入与愉快可以加分；不能把普通聊天一概当作不调分。纯查询、索要分数、重复刷话和无实际交流的客套不加分，不设调用配额、随机加分概率或固定消息比例。先判断关系变化，再选择方向与幅度。轻微但明确的变化通常参考 0.01～0.03 分，较有意义的互动允许更明显变化，幅度越大依据越充分。参考范围仍受当前额度限制，单次上限不是建议值。不固定按十分之一分调整，也不强制所有互动都用最小值；相似互动可以同分，不随机凑小数。扣分更谨慎，合理批评、纠错、拒绝和熟人玩笑不扣分，判断不清则不调整。
- 工具必须提供本轮真实发言者 QQ、消息编号、最多两位小数的非零变化值（精度 0.01 分）和 1~200 字简短依据，不输出思考过程。对象必须匹配消息作者，只接受当天且在 AI 模式中记录的本轮互动。没有可靠编号则不调分，不从历史记录猜对象。
- 同条互动在当前会话只能有效评分一次；去重和额度持久化，重试、并发调用、重启或切换模式不能重复计分。工具按单次额度、当日余额和分数下限计算实际变动并返回。
- 常见纯好感度查询会被工具拦截；复杂语义仍由主模型判断。查询不触发额外 AI 评分。本人真实发言更新最近互动时间，单纯后台读取或反复读取同条消息不会更新它。
- 默认不播报每次加减，继续正常对话。每个会话保留最近 200 条 AI 调分记录（消息编号、变动前后分数、时间、简短理由）；个人查询展示最近三条。重置相应成员时同步清理相关调分记录和旧证据。

语义判断由主模型完成，程序只能验证身份、证据编号、额度与重复操作，不能保证模型不会误判玩笑或冒犯。调分工具不发送消息、不读取宿主全局配置、不调用额外模型；正常工具循环可能增加主会话轮数和用量。

### 长期关系淡化

按已过去的完整天数惰性结算，查询不会重复扣分。真实互动先结算之前的闲置期，再更新最近互动时间；关闭或调整淡化配置时记录边界，关闭期间不在重新开启时补算。分数淡化影响社交距离，**不会删除主程序记忆，也不代表模型真的忘记用户**。首次计分时间与最近互动时间继续可查询。

查询示例：“我的好感度”“我们现在有多熟”“好感度排行”。配置主人后，主人可说“把回复变化强度改成 3”“把高好感表达风格改成温柔关心”。

查询和排行榜工具只返回数据，不自动发送 QQ 消息。主会话模型应先查询，再调用 `send_message` 按当前人设回复；工具说明、提示词和查询结果均提示这个顺序。低好感只影响社交语气，不表示可以忽略明确查询。没有记录、目标不明确或查询出错时，同样需要向提问者说明。模型若只把答案写在普通正文中，QQ Agent 仍可能以 `noreply` 结束；插件不把正文或思考直接转发，也不调用额外模型绕过宿主流程，无法硬性保证模型一定执行发送。

报告中的“首次计分记录”表示本插件开始记录该成员的时间，不是成员入群时间，不能据此推断“今天刚进群”。本次修正不改动已有分数和历史记录。

聊天修改保存在本插件数据的 `meta.overrides` 中，优先于控制台设置。主人可要求清除某项或全部聊天修改，恢复控制台值。模糊的同名目标需要用 QQ 号明确指定；无法唯一确认发送者的修改请求不会执行。

## 独立数据

- 插件 ID、工具前缀、配置分区均为 `rapport`。
- 百分制数据文件仍为 QQ Agent 数据目录中的 **`rapport.json`**，格式版本为 2。
- 数据带有本插件的 `pluginId` 和格式版本标记。
- **不读取、导入或迁移其他好感度插件的分数、主人名单和配置。首次使用从本插件的新记录开始。**

计分在机器人被触发时补扫当前会话最近 200 条消息，范围限于最近 24 小时。新安装时可以统计此范围内的聊天消息，这不是从其他插件导入数据。超出补扫范围且未被处理的消息不会补记。

普通模式的每日上限、机械冷却和重复内容去重同时生效，AI 模式使用上面的独立规则。读取 QQ Agent 存档中的 `atMe` 标记；本地序号和 QQ 消息 ID 分开去重，迟到的历史消息不会重置今天的额度。

当前 QQ Agent 0.4.0 将引用信息渲染为文字，没有向插件提供可靠的引用消息 ID，因此不设置引用奖励，也不根据昵称或引用文字猜测加分。昵称信息缺失时，只有查询工具会调用 `get_group_member_info` 补全，接口失败仍可用 QQ 号查询。

原子写入保护存档；格式不匹配或嵌套数据损坏时停止写入并报错，不静默清零。停用时同步保存已完成的变更，并取消尚未完成的处理，适应宿主不等待异步清理的加载流程。

AI 调分、聊天设置和重置在同步事务中保存，保存失败会回滚本次修改（包含额度、去重标记与审计记录）；恢复写入后不会补交已报告失败的操作。查询在等待昵称补全后重新读取当前记录，避免并发回滚或重置造成旧数据回复。只切换 AI/普通模式不重置衰减计时；修改衰减规则时才按旧规则结算并启用新起点。

AI 提示中的证据列表会过滤已评分、主人保护和冷却中的对象。额度已满、没有证据或工具拒绝时不连续重试，也不为调分先调用查询工具；执行工具时仍独立校验消息、身份、额度和幂等性。

兼容宿主内联工具解析产生的数字 QQ 号和消息编号，仅将安全整数无损转换为文本（QQ 消息编号允许负数），不放宽作者和消息证据校验。“好感度排行榜”等常见纯查询同时从提示候选与执行入口排除；语义复杂的查询仍由主模型遵守不调分规则。

本轮使用过 rapport 工具或已授权的外部扩展工具后，公开 `before-tool` 钩子会对照 `session.sent` 阻止 `send_message` 重发完全相同的已成功发送文字，引用方式不同也算重复。混有新旧文字的批次会整体拒绝并提示只发送新内容；失败未发送的文字仍可重试。防护仅限同一会话，不拦截跨会话工具、不撤回消息、不替模型发言；停用时清除会话标记。

待发文字先在插件内按当前 QQ 格式规则解包 JSON 字符串/消息对象并转换 Markdown，再与实际已发送文字比较；链接地址和换行等有效差异保留。已发送文字不重复转换。此过程不导入宿主模块、不读取发送配置；不预测宿主按配置对超长文字的拆分，也不拦截仅语义相似的改写。

插件不主动增加群消息或私聊，不额外发送升级提示。

## 开发

`before-context` 每轮记录互动并在普通模式计分，`promptSections` 提供动态关系与 AI 调分规则，优先级不超过 65。查询、设置和 AI 调分通过 `registerTool` 提供给主模型。

钩子不联网、不调用额外模型、不发送消息。关系规则遵守 QQ Agent 核心安全与工具协议；高好感不会赋予管理权限。生命周期会清理定时器与运行缓存。

入口只负责加载模块和导出插件接口，业务代码按职责拆分：

```text
plugin.json
index.js
lib/
  plugin.js          实例组装、生命周期和钩子
  config.js          配置、校验和聊天覆盖
  levels.js          等级、衰减和主人规则
  points.js          百分制边界、两位小数与整数精度运算
  messages.js        消息解析
  scoring.js         去重、防刷和计分
  events.js          通用事件 API、来源权限与持久化去重
  migrations.js      本地试用回执迁移
  storage.js         独立存档与原子保存
  relationship.js    关系缓存与回复风格
  reply-guard.js     本轮已发送文字的公开钩子去重
  reply-text.js      待发文字的格式归一化，仅用于重复比较
  utils.js           通用纯函数
  tools/
    index.js         工具注册和参数校验
    context.js       身份校验和查询辅助
    check.js         个人查询
    rank.js          排行榜
    tune.js          设置管理
    reset.js         重置记录
    adjust.js        AI 调分的证据、限额、幂等性和审计
README.md
```

所有业务模块使用普通静态 `import`，插件不为 JS 路径追加版本参数。子模块通过工厂创建独立实例，依赖由 `lib/plugin.js` 显式组装。

当前 QQ Agent 的热重载只重新执行入口，不清除 Node 的 ESM 子模块缓存。因此，修改 `lib/` 中的代码后，需要重启 QQ Agent 才能确保新代码生效；首次安装和配置调整不需要这样处理。这里遵循标准模块加载，不实现额外的文件更新或缓存绕过机制。

运行环境为 Node.js 20 或以上版本。开发命令由合集仓库根目录的 `package.json` 统一维护，插件目录不需要单独的 npm 包配置。在仓库根目录运行 `npm test -- rapport` 可执行通用检查、查询回复和 AI 计分回归测试（使用隔离存档，不读取真实用户数据）；运行 `npm run pack:extension -- rapport` 可打包本插件。

发布包包含根目录的 `plugin.json`、`index.js`、`README.md`、`API.md`、接入示例和完整 `lib/` 目录。不要将 Git 信息、配置或运行数据加入发布包。

开发接口依据：[QQ Agent 官方扩展文档](https://github.com/K0nd1us/QQ-agent/tree/main/doc/extend_development)。
